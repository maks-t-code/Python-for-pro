# 🏃‍♂️ Прогнозирование сожженных калорий с помощью ансамблей моделей машинного обучения

Этот проект представляет собой комплексное исследование и сравнение различных алгоритмов машинного обучения, применяемых для задачи регрессии — прогнозирования количества сожженных калорий на основе физических параметров. В основе работы лежит использование мощных ансамблевых методов: **Random Forest**, **XGBoost**, **LightGBM** и **CatBoost**.

Проект был выполнен в рамках домашнего задания по теме "Машинное обучение. Ансамбли моделей" на основе данных популярного соревнования [Playground Series - Season 5, Episode 5](https://www.kaggle.com/competitions/playground-series-s5e5) с платформы Kaggle.

---

## 🎯 Цель проекта

Основная цель — построить и сравнить несколько моделей машинного обучения, чтобы определить наиболее точный и стабильный алгоритм для предсказания целевой переменной (`Calories`). В ходе работы были решены следующие задачи:

*   Проведение разведочного анализа данных (EDA) для понимания структуры и распределения признаков.
*   Предобработка данных: кодирование категориальных признаков и масштабирование числовых.
*   Обучение четырех различных ансамблевых моделей.
*   Оптимизация гиперпараметров с помощью `GridSearchCV`.
*   Сравнение моделей по ключевым метрикам регрессии.

## 📊 Данные

**Источник:** [Kaggle Playground Series - Season 5, Episode 5](https://www.kaggle.com/competitions/playground-series-s5e5)

**Набор данных содержит 750,000 записей и 9 столбцов:**

*   `id`: Уникальный идентификатор записи.
*   `Sex`: Пол (male/female).
*   `Age`: Возраст (в годах).
*   `Height`: Рост (в см).
*   `Weight`: Вес (в кг).
*   `Duration`: Длительность тренировки (в минутах).
*   `Heart_Rate`: Частота сердечных сокращений (в ударах в минуту).
*   `Body_Temp`: Температура тела (в градусах Цельсия).
*   `Calories`: **Целевая переменная** — количество сожженных калорий.

## 🔍 Разведочный анализ данных (EDA)

Перед построением моделей был проведен первичный анализ данных, который показал:

*   **Корреляция:** Признаки `Duration`, `Heart_Rate` и `Body_Temp` имеют сильную положительную корреляцию с целевой переменной. Признак `id` был исключен из обучения из-за отсутствия влияния.
*   **Пропуски:** Пропуски в данных отсутствуют, что упростило предобработку.
*   **Выбросы:** Небольшие выбросы были обнаружены в признаках `Height`, `Weight`, `Heart_Rate` и `Body_Temp`. Однако они соответствуют нормальным физиологическим значениям и не были удалены.
*   **Категориальные признаки:** Признак `Sex` закодирован с помощью One-Hot Encoding для моделей, которые не поддерживают категориальные данные из коробки.
*   **Целевая переменная:** Распределение `Calories` близко к нормальному, без значительных выбросов.

## 🤖 Модели и результаты

Для обучения и сравнения были выбраны четыре ансамблевые модели. Для каждой модели проводился подбор гиперпараметров с помощью `GridSearchCV` с использованием метрики **Mean Absolute Error (MAE)** для оптимизации.

| Модель | Mean Squared Error (MSE) | Mean Absolute Error (MAE) | Mean Absolute Percentage Error (MAPE) | Время обучения (относительно) | Комментарий |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **XGBoost** | **~87.47** | **~6.64** | **~0.162** | Среднее | **Лучшая по метрикам** и стабильности. |
| **Random Forest** | ~13.66 | ~2.20 | ~0.038 | Высокое | Показал низкие ошибки, но заметное переобучение (разница в MSE на трейне и тесте). |
| **LightGBM** | ~13.33 | ~2.20 | ~0.039 | Низкое | Очень быстрый и близкий к Random Forest по качеству. |
| **CatBoost** | ~2237.81 | ~39.72 | ~1.61 | Низкое | Требует минимальной предобработки, но показал худший результат. |

### 📈 Итоговый вывод

*   **Лучшая модель:** **XGBoost**. Эта модель продемонстрировала наилучший баланс между точностью предсказаний (`MAE`) и скоростью обучения. Она была признана **самой стабильной и лучшей по метрикам**.
*   **Самая простая в обработке:** **CatBoost**. Модель способна работать с категориальными признаками "из коробки", что значительно упрощает этап предобработки данных. Однако, в данном эксперименте это преимущество не компенсировало низкое качество прогнозов.
*   **Рекомендация:** Для решения данной задачи наилучшей является модель **XGBoost**, как по качеству прогноза, так и по стабильности работы.
