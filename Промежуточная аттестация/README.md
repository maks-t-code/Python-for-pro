## Задание 2: Оптимизация запроса к БД (Схема EAV)

### 🔍 Анализ проблемы

В базе данных используется схема **EAV (Entity-Attribute-Value)** с двумя таблицами:

#### Структура таблиц

```sql
-- Таблица пользователей
CREATE TABLE users (
    id int PRIMARY KEY,
    full_name varchar(100)
);

-- Таблица метаданных пользователей (EAV)
CREATE TABLE users_meta (
    id int PRIMARY KEY,
    user_id int REFERENCES users(id),
    meta varchar(16),      -- Название атрибута
    meta_value varchar(64) -- Значение атрибута
);
```

#### Проблема исходного запроса

```sql
-- Исходный запрос (неэффективный)
SELECT DISTINCT users.id
FROM users 
    INNER JOIN users_meta AS mt1 ON (users.id = mt1.user_id)  
    INNER JOIN users_meta AS mt2 ON (users.id = mt2.user_id)  
    INNER JOIN users_meta AS mt3 ON (users.id = mt3.user_id)
    INNER JOIN users_meta AS mt4 ON (users.id = mt4.user_id)
WHERE 1=1 
AND ((mt1.meta = 'birth-date' AND mt1.meta_value != '') 
  OR (mt2.meta = 'phone-number' AND mt2.meta_value != '') 
  OR (mt3.meta = 'activity-flag' AND mt3.meta_value != '')
  OR (mt4.meta = 'register-date' AND mt4.meta_value != '')
);
```

### 🚨 Выявленные проблемы

1. **Избыточные JOIN**: Таблица соединяется 4 раза с разными псевдонимами
2. **Проблемы производительности**: При росте количества атрибутов количество JOIN увеличивается экспоненциально
3. **Неэффективное использование ресурсов**: Создается излишняя нагрузка на БД
4. **Проблемы масштабируемости**: Не масштабируется для систем с большим количеством атрибутов

### ✅ Решение

**Оптимизированный запрос:**
```sql
SELECT DISTINCT users.id
FROM users 
    INNER JOIN users_meta AS mt ON (users.id = mt.user_id)
WHERE 1=1 
AND ((mt.meta = 'birth-date' AND mt.meta_value != '') 
  OR (mt.meta = 'phone-number' AND mt.meta_value != '') 
  OR (mt.meta = 'activity-flag' AND mt.meta_value != '')
  OR (mt.meta = 'register-date' AND mt.meta_value != '')
);
```

### 🎯 Улучшения

| Аспект | Исходный запрос | Оптимизированный |
|--------|-----------------|------------------|
| **Количество JOIN** | 4 | 1 |
| **Производительность** | Низкая (O(n) JOIN) | Хорошая (фиксированное число JOIN) |
| **Масштабируемость** | ❌ Не масштабируется | ✅ Масштабируется |
| **Использование ресурсов** | Высокое | Низкое |

### 💡 Рекомендации по оптимизации

1. **Используйте один JOIN**: Всегда используйте одно соединение для EAV-таблиц
2. **Создайте индексы**: Добавьте индексы на колонки `user_id` и `meta`
3. **Избегайте множественных JOIN**: Множественные JOIN одной таблицы редко необходимы
4. **Рассмотрите денормализацию**: Для часто запрашиваемых атрибутов можно использовать денормализацию

### 🔧 Рекомендуемые индексы

```sql
-- Улучшение производительности оптимизированного запроса
CREATE INDEX idx_users_meta_user_id ON users_meta(user_id);
CREATE INDEX idx_users_meta_meta ON users_meta(meta);
```
