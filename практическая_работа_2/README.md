# Прогнозирование оттока клиентов банка на основе методов классификации (Python)

Проект посвящен построению высокоточной модели машинного обучения для задачи бинарной классификации — предсказания того, останется ли клиент с аккаунтом в банке или закроет его (`Exited`). Исследование основано на структурированных исторических данных о поведении клиентов, их демографических признаках и финансовых показателях (датасет конкурса **Kaggle Playground Series - Season 4, Episode 10**).

---

## 📊 Описание признаков датасета

| Признак | Тип данных | Описание |
| :--- | :--- | :--- |
| **CreditScore** | Числовой | Кредитный рейтинг клиента |
| **Geography** | Категориальный | Страна проживания (`France`, `Spain`, `Germany`) |
| **Gender** | Категориальный | Пол клиента (`Male`, `Female`) |
| **Age** | Числовой | Возраст клиента (в годах) |
| **Tenure** | Числовой | Сколько лет человек является клиентом банка |
| **Balance** | Числовой | Баланс на счете клиента |
| **NumOfProducts** | Числовой | Количество банковских продуктов, используемых клиентом |
| **HasCrCard** | Бинарный | Наличие кредитной карты (`0` — нет, `1` — да) |
| **IsActiveMember**| Бинарный | Статус активного клиента (`0` — нет, `1` — да) |
| **EstimatedSalary**| Числовой | Предполагаемая заработная плата клиента |
| **Exited** | Бинарный | **Целевой признак**: факт закрытия аккаунта (`0` — остался, `1` — ушел) |

## 💡 Этапы реализации проекта

### 1. Разведочный анализ данных (EDA)
* Проведен аудит структуры датасета. Объем занимаемой памяти составил **~39.73 MB** (165 034 строки, 14 столбцов).
* На основе построенной тепловой карты линейной корреляции Пирсона было установлено, что технические идентификаторы (`id`, `CustomerId`), а также фамилия клиента (`Surname`) не имеют статистической значимости и корреляции с целевой переменной. Данные признаки были исключены из признакового пространства `X`.
* С помощью диаграмм размаха (Boxplot) проанализировано распределение непрерывных признаков на наличие выбросов и аномалий. Все экстремальные значения признаны физиологически и экономически допустимыми, в связи с чем удаление строк не потребовалось.
* Выявлен умеренный дисбаланс классов в целевом признаке: доля ушедших клиентов (`Exited = 1`) составляет **21.16 %**.

### 2. Предобработка данных и кодирование
* Данные разделены на обучающую (`train`) и тестовую (`test`) выборки в соотношении 75/25 с обязательным применением **стратификации** (`stratify=y`) для сохранения исходного соотношения классов.
* Для категориальных признаков `Geography` и `Gender` применено бинарное кодирование с помощью `OneHotEncoder(drop='first', sparse_output=False)` во избежание мультиколлинеарности (ловушки фиктивных переменных).
* Все числовые (непрерывные) признаки стандартизированы с помощью `StandardScaler` (Z-масштабирование), что критически важно для корректной работы линейных моделей.

### 3. Обучение моделей и оценка качества
В рамках исследования были обучены и сопоставлены две архитектуры:
1. **Базовая логистическая регрессия** (`LogisticRegression`) без штрафов.
2. **Логистическая регрессия с $L_2$-регуляризацией (Ridge)** для предотвращения переобучения модели и стабилизации весов.

## 📈 Результаты моделирования и метрики качества

Качество классификации на отложенной тестовой выборке оценивалось по комплексу метрик: `Accuracy`, `Precision`, `Recall`, `F1-score` и площади под ROC-кривой (`ROC-AUC`).

| Архитектура модели / Метрика | Accuracy | Precision | Recall | F1-score | ROC-AUC |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Базовая логистическая регрессия** | 0.83 | 0.69 | 0.38 | 0.49 | 0.815 |
| **Логистическая регрессия с $L_2$-регуляризацией** | 0.83 | 0.69 | 0.38 | 0.49 | 0.815 |

### Аналитические выводы:
* Модели продемонстрировали абсолютно идентичные и стабильные результаты на тестовых данных, что обусловлено большим объемом выборки и хорошей предобработкой признаков.
* Площадь под ROC-кривой (**ROC-AUC = 0.815**) свидетельствует о высоком качестве разделения классов и хорошей предсказательной способности построенного алгоритма по сравнению со случайным классификатором.
* В качестве финального решения для промышленной эксплуатации **рекомендуется использовать модель логистической регрессии с $L_2$-регуляризацией**, так как наличие штрафа за сложность гарантирует более высокую устойчивость модели при поступлении новых, зашумленных данных.
